Testing

09 • Testing

How we tested and what we learned

Testing has been used to find weaknesses in the recommendations, check that new features save information correctly, and guide the next round of improvements. The results described here are prototype-development findings, not clinical validation.

1. Initial test

We began by testing the early prototype with five test subjects. We compared the sleep recommendations it produced and checked whether the results seemed individualized.

2. Main issue found

The first version recommended the same 22:00 sleep time to everyone. This showed that the prototype was not responding enough to differences between users.

3. Changes made

We expanded the sleep planner so it could consider more information instead of relying on one general sleep time.

Inputs we now check

  • Recent sleep history and estimated sleep debt
  • Hours the person has been awake
  • Previous fatigue score
  • Caffeine recorded for the day
  • Assigned work shift
  • Mission events and possible sleep conflicts
  • Check-in alertness rating
  • How effective the previous recommendation was

App and data checks

  • Generated sleep plans and saved recommendations
  • Check-ins recording sleep and feedback
  • Feedback linked to the recommendation being rated
  • History displaying check-ins and saved recommendations
  • Different views for crew members and managers
  • Database version update and retention of existing data during migration
  • Flutter Analyzer to check the code for reported issues

What testing has shown so far

The first test revealed that a fixed sleep time was not enough. As the prototype developed, the planner gained more inputs related to sleep, fatigue, caffeine, shifts, mission events, and feedback. These changes make the plan more responsive to the information entered, but they do not prove that every recommendation is correct or medically validated. Some different inputs may still produce similar results, so the scheduling logic needs continued refinement.

What we still need to test

  • Combinations of short sleep, high fatigue, long hours awake, and caffeine use.
  • Mission events that overlap with a planned sleep period, including several conflicts on the same day.
  • Changes between Night, Morning, and Evening shifts.
  • Whether plans remain reasonable when little or no sleep history is available.
  • Whether repeated check-ins and effectiveness ratings consistently influence later recommendations.
  • Whether each role sees only the appropriate information when tested across more accounts and devices.
  • More test cases with different users and edge cases before making stronger claims about performance.
